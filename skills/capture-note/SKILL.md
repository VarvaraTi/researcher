# Capture Note

Resolve plugin resources and workspace paths using [runtime locations](../../docs/plugin.md#runtime-locations) before running commands. Keep personal data in the working workspace, never in the installed plugin.

Store visual note attachments and diagrams inside the same course/study and link them from the attributed note and relevant topic/sheet, following [visual learning assets](../../docs/learning-operations.md#visual-learning-assets). Preserve exact learner additions.

Retrieve the related course context through okf:retrieval. Preserve the learner’s exact text in a Note body, author and UTC timestamp; publish through the shared gate. Propose links to existing topics, lessons, exercises or sources rather than inventing relationships from keywords. Keep assistant commentary in separately attributed records.

For questions, use Question with question_status open/exploring/resolved and preserve original wording plus attributed discussion and evidence. Resolution does not demonstrate linked objectives. Replacing learner wording requires an explicit learner action; additions and assistant corrections are separate by default.

Personal cheat-sheet additions are Note records linked from personal_additions; content updates must not overwrite them. Use simple tables/Mermaid when helpful, label assistant-created visuals, cite supporting passages and include a text fallback. Follow operations for export and explicit deletion, inspecting dependencies first.
