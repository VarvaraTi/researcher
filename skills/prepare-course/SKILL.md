# Prepare Course

Resolve plugin resources and workspace paths using [runtime locations](../../docs/plugin.md#runtime-locations) before running commands. Keep personal data in the working workspace, never in the installed plugin.

Plan learner visual assets inside the selected course/study using [visual learning assets](../../docs/learning-operations.md#visual-learning-assets); project docs and temporary previews are not course storage.

Classify the requested study before creating storage: standalone articles reuse `learning.articles` at `courses/articles/`; a full course with its own curriculum (such as System Design Alex Xu) gets a separate bundle. An article added to an existing full course stays there; a new topic or chapter never creates a bundle. Use okf:init and okf:ontology only when the selected bundle does not exist; use article-ontology.yaml for shared articles and course-ontology.yaml for full courses, using the matching [article](../../templates/article-bundle.yaml) or [course](../../templates/course-bundle.yaml) manifest and versioned [default policies](../../policies/defaults/). Merge existing registrations/settings instead of replacing them; follow bundle guidance for schema installation. Create each article as Study at `studies/<slug>/study.md`, all records inside its folder with explicit study ownership. Use simple domains labels, not Domain records. Select the bundle ID in learning.local.json.selected_course and the Study ID in selected_course_record; pass that Study as context.study, including creation in the same changeset. Full-course contexts omit study. Use the selected study's inspect-state for complete history, with bundle-wide next_sequence; do not manually filter sampled results. Root navigation/schema maintenance is separate from study-scoped publication. Use okf:migrate for authored material or okf:ingest for repositories/mixed artifacts. Follow their preflight and provenance requirements.

Collect the concrete goal and selected material. Articles and books can vary per course. Search for additional sources only when requested; discovery is not permission to include them. Inspect available passages with precise headings/pages/paragraphs. Record inaccessible, partial or conflicting material as a limitation; request accessible excerpts when necessary. Do not claim to have read a paywalled article or whole book from a preview.

For a local PDF on macOS, use `sh "$LEARNING_PLUGIN_ROOT/scripts/read-pdf.sh" '/path/book.pdf'` from the learning workspace (first 12 pages), then `--pages 13:25` for a bounded range or `--all` when the whole text is needed. The helper uses Swift/PDFKit without third-party packages and writes text to stdout; redirect to a private temporary file if needed. It requires macOS and Swift Command Line Tools. Cite the emitted 1-based PDF page numbers separately from printed page labels. Extraction does not inspect images, diagrams or layout and performs no OCR. Empty text is not proof of an empty page; inspect relevant visuals separately or report the limitation. Retain used extracts/source versions through the normal OKF publication workflow, not by redirecting into bundle concepts.

Propose objectives, topics, prerequisite edges, workload estimates and three planning levels: course map, near-term detail, session. Run check-prerequisites on prerequisite edges only. Related-topic cycles are allowed. Define each objective’s versioned evidence contract: named criteria and allowed evidence kinds (e.g. explanation, application, recall). Discussion without a practical task is allowed. No universal mastery threshold.

Show the map for learner acceptance. Save acceptance evidence with the immutable accepted version and link Study.accepted_plan (articles) or Course.accepted_plan (full courses) only after acceptance; a changed general plan gets a new version. Prepare only near-term lessons after acceptance. Calendar dates require explicit timezone/study days and accepted time budget. Use compute-schedule and retain visible overflow. Estimates are approximate.

When setting up a new full course, check whether a course map was requested for that course. If requested, add its display configuration to the Course record and enable it before generating the initial HTML map from the accepted plan. Generate the map after the accepted plan is saved, and provide its stable course-local entry link. Map creation is an explicit workflow step performed by this skill via `node scripts/update-course-map.mjs --bundle <course-bundle>` (use the plugin runtime path when installed); it does not happen automatically on disk. Do not enable maps for every new course by default, and do not create course maps for standalone article studies.

Grounding review is semantic, beyond schema validation. Never mark unsupported content ready. Retain source snapshots/locators used by historical content. Follow okf:update for source drift, reviewing affected records before creating replacement versions; do not overwrite prior attempts, source snapshots or learner additions.

For an opted-in full course (`Course.course_map.enabled`), refresh its [course map](../../docs/learning-operations.md#course-maps) after the saved plan, lesson, session, assessment or revealed-reference changes made in this workflow. Use the stable course-local entry link; keep coverage separate from evidence and planned stages separate from prepared lessons. Do not enable maps for unrelated courses or studies.

## Shared selected books

For a newly selected full book, follow [shared-library operations](../../docs/learning-operations.md#shared-book-library): on-demand setup, edition/digest reuse, all-page extraction, retained PDF and guarded library publication precede course linkage. A partial run exposes gaps and permits preparation from supported passages; it does not make unsupported chapters ready. Keep full-book indexing separate from progressive lesson preparation and learner acceptance of the plan. Preserve existing local Source references and historical versions. Publish optional Course.shared_source_refs and Topic/Lesson/CheatSheet shared reference fields with explicit library scope. Changed bytes/editions need an explicit update decision; repeated preparation reuses a usable matching index. Do not migrate the live Alex Xu course without its separate rollout authorization.
